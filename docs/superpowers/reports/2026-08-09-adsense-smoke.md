# 애드센스 병행 도입 — 브라우저 스모크 결과

- 실시일: 2026-08-10
- 대상: 계획 [`2026-08-09-adsense-integration.md`](../plans/2026-08-09-adsense-integration.md) Task 11
- 퍼블리셔 ID: `ca-pub-2785578834914321`
- **전제: 애드센스 심사 전이다. 광고가 채워지지 않는 것(`unfilled` → 접힘)이 정상 경로이며, 광고가 안 보인다고 결함으로 판정하지 않는다.**

## 실시 방법과 그 이유 (계획 대비 편차)

계획 Step 1~3은 `flutter run -d chrome` + admin에서 슬롯 전환을 전제한다. **실제로는 그 경로로 갈 수 없었다**: 이 앱은 인증 토큰을 **메모리에만** 보관하므로(`api_providers.dart:14` — "localStorage 영속화는 후속") 세션 주입으로 로그인을 우회할 수 없고, 광고 슬롯 3곳은 전부 `router.dart:84`의 `gateRedirect` 뒤에 있다. 실 로그인은 GitHub OAuth 자격증명이 필요하다.

그래서 검증 대상을 **위젯 테스트로 도달 불가능한 실제 위험**으로 좁혀, 두 층에서 실측했다.

| 층 | 방법 |
|---|---|
| A. 심(`createDevpathAdUnit`) 자체 | 릴리스 산출물 `build/web`을 http로 서빙하고 Playwright(Chromium)로 로드해 **진짜 `adsbygoogle.js`** 를 받은 뒤 심을 직접 호출 |
| B. Flutter 플랫폼 뷰 경로 | 전용 프로브 엔트리포인트(`-t`)로 `AdSenseUnitView`만 마운트해 릴리스 빌드 → 같은 방식으로 관측. **프로브 파일은 커밋하지 않았다** |

미실시: admin UI에서의 슬롯 전환·원복(Step 3·9), 애드블록 확장 상태(Step 7). 전자는 로그인 벽, 후자는 확장 설치가 필요하다.

## A. 심 동작 — 전부 기대대로

| 확인 | 결과 |
|---|---|
| `/ads.txt` 서빙 | **200**, `google.com, pub-2785578834914321, DIRECT, f08c47fec0942fa0` |
| `window.createDevpathAdUnit` 정의 | **true** |
| `adsbygoogle.js?client=ca-pub-2785578834914321` | **200** (퍼블리셔 ID가 틀리면 404다 → ID 유효) |
| 폭 있는 컨테이너(728px) | `<ins>` 1개 삽입, 폭 728, `data-ad-status="unfilled"`, **1118ms**에 접힘(height 0) |
| `dispose()` | `<ins>` 1개 → **0개** (DOM에서 제거됨) |

### 계획검토에서 고친 두 가지가 실제로 작동함

**① 폭 0 게이트** — 폭 0 컨테이너에 심을 걸었을 때 `data-ad-status`가 **`null`인 채로 8000ms 타임아웃**에 접혔다. 즉 **push를 보류했다**(구글이 `<ins>`를 건드리지 않았다는 뜻). 초안대로 즉시 push했다면 `availableWidth=0` 거부가 났을 자리다.

**② 나중에 폭이 생기는 경로** — 폭 0으로 시작해 1초 뒤 728px을 주자 **2080ms에 `data-ad-status="unfilled"`, `insWidth 728`** 로 해결됐다. rAF 루프가 폭이 생긴 시점에 push했고 구글의 **실제 응답**을 받았다. (대조군: 처음부터 폭이 있으면 1113ms, 동일 결과.)

> ⚠️ 최초 관측에서 이 항목이 `data-ad-status` 없이 1005ms에 접혀 결함으로 보였으나, **격리 재현 결과 테스트 하네스가 앞선 `<ins>`를 DOM에 남긴 아티팩트**였다. 페이지에 `<ins>`가 하나뿐인 상태로 다시 재면 위와 같이 정상이다.

## B. Flutter 플랫폼 뷰 경로 — 핵심 위험 해소

`AdSenseUnitView`를 실제로 마운트한 상태에서:

| 확인 | 결과 |
|---|---|
| `<ins>` 삽입 | **1개** |
| **컨테이너 폭** | **1400** (0이 아니다 — 폭 게이트 통과) |
| `data-ad-status` | **`unfilled`** |
| 광고 요청 `googleads.g.doubleclick.net/pagead/ads?client=ca-pub-2785578834914321` | **200** |
| 콘솔 오류 (`availableWidth=0` · `already have ads in them`) | **0건** |

이것이 이번 스모크의 핵심이다. 스펙이 근거로 든 Monaco 선례는 **컨테이너 크기를 요구하지 않는** 위젯이라 이 위험을 검증해 주지 못했다(그래서 `height:100%`를 준다). 「DOM 삽입이 가능하다」와 「애드센스가 그 안에서 채워진다」는 다른 주장이고, 후자를 여기서 처음 실측했다.

## C. 재진입 — 누적·중복 없음, 다만 재요청도 없음

프로브에 타이머를 넣어 언마운트↔재마운트를 반복시키고(3초 주기 3회, 10초 주기 2회) 관측했다. Flutter는 캔버스에 그리므로 DOM 클릭이 통하지 않아 **`document.title`에 세대 표식**을 남겨 토글이 실제로 일어났음을 확인했다(`gen0-mountedfalse` → `gen1-mountedtrue` → … → `gen2-mountedtrue`).

| 확인 | 결과 |
|---|---|
| 문서 내 `<ins>` 최대 개수 | **1** (누적 없음) |
| `already have ads in them` 오류 | **0건** |
| 광고 요청 횟수 | **1건** (재마운트 2~3회에도 늘지 않음) |

계획 Step 6이 우려한 **누적·중복 삽입은 증상이 없다.**

**다만 재마운트가 새 광고 요청을 유발하지 않았다.** 10초 주기(심의 8초 마감선보다 길게)로 다시 재도 요청은 1건이었다. 심사 전이라 어차피 전부 `unfilled`이므로 지금은 영향이 없지만, **승인 이후에는 "슬롯이 한 번 `unfilled`로 접히면 전체 새로고침 전까지 다시 채워지지 않는" 동작일 수 있다.** 승인 후 재확인이 필요한 항목으로 남긴다. (참고로 네비게이션마다 광고를 다시 요청하는 것은 애드센스 정책상 권장되지 않으므로, 이 동작이 오히려 안전한 쪽일 수도 있다 — 판단에 실측이 더 필요하다.)

## D. 미해결/이월

| 항목 | 사유 |
|---|---|
| admin에서 슬롯 전환·원복 (Step 3·9) | 로그인 벽(토큰 메모리 보관). 백엔드 API 자체는 `AdSlotConfigApiTest` 4건으로 커버됨 |
| 애드블록 상태 (Step 7) | 확장 설치 필요. 다만 "응답 없음"은 폭 0 게이트 실험에서 **8초 타임아웃 → 접힘**으로 동일 경로가 실증됨 |
| 실제 광고 단위 ID | 아직 없다. 위 실측은 임시값 `1234567890`을 썼다 |
| 승인 후 실제 노출 | 심사 전. 그리고 **광고 3슬롯이 전부 로그인 뒤 화면이라 크롤러가 도달할 수 없다** — 계획의 「수용된 위험」 절 참조 |
| viewFactory 등록 누적 | Flutter web에 unregister API가 없다. 문서 내 `<ins>`는 늘지 않았으나 detached 요소·팩토리 등록 자체는 이 방법으로 관측 불가 |

## 결론

**계획검토에서 고친 두 결함(폭 0 push, `window.adsbygoogle` 부재 레이스)이 실제 브라우저에서 의도대로 동작함을 확인했다.** 심사 전 기대 상태인 "스크립트 200 로드 → `<ins>` 삽입 → `unfilled` → 접힘"이 심 단독 경로와 Flutter 플랫폼 뷰 경로 양쪽에서 재현됐고, 중복 삽입·`availableWidth=0` 오류는 한 건도 없었다.
